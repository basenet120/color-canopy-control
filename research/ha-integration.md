# ha-integration

**HEADLINE:** The Home Assistant/aioafero ecosystem proves Hubspace cloud control is per-device-command only (no group/scene primitives, no transitions), throttled per account with 429/503 retries and a hardcoded 3-connection HTTP cap, so a stock Python bridge cannot hit a <2s first-to-last spread on 200 bulbs without patching concurrency, splitting accounts, and/or offloading animation to on-bulb sequence effects — while the days-old (Sep 15, 2026) Conclave push channel finally gives near-real-time state feedback.

## Findings
- [HIGH] **The canonical community integration is jdeath/Hubspace-Homeassistant v8.3.0 (Sep 15, 2026) built on Expl0dingBanana/aioafero 9.3.0 (PyPI, Sep 15, 2026); the library was renamed from aiohubspace to aioafero at aioafero 2.0.0 (Apr 29, 2025) and previously superseded hubspace-async — report current names aioafero/Hubspace-Homeassistant, not aiohubspace.**
  - Integration manifest pins aioafero==9.3.0, iot_class cloud_polling, requires Python >=3.12 for the lib; repo has 381 stars, 65 forks, created Mar 2022, pushed Sep 15 2026, 0 open issues (actively triaged). Release cadence is intense: 8.0.0 Aug 9, 8.1.0 Sep 13, 8.2.0 Sep 14, 8.3.0 Sep 15, 2026 — expect churn during the install window; pin versions for the show.
  - src: https://github.com/jdeath/Hubspace-Homeassistant/releases and https://pypi.org/project/aioafero/
- [HIGH] **Supported device types cover every vignette need except true humidifiers: RGB/CCT lights (incl. LED string/strip lights with 'sequence' preset effects), plugs/outlets, switches, ceiling/exhaust fans, Defiant locks (lock/unlock/battery), water-timer valves, thermostats, portable ACs, dehumidifiers, security systems.**
  - aioafero ships typed controllers: light, switch, fan, exhaust_fan, lock, valve, thermostat, portable_ac, dehumidifier, security_system(+keypad/sensor), device. Lights expose color-mode values color/white/sequence/mixed; dual-channel RGB+WW fixtures split into two HA entities (v7.0.0+). Dehumidifier support landed v8.1.0 via HA humidifier platform — a plain humidifier device class is NOT listed, so bench-verify the bedroom humidifier SKU early. String-light gaps documented: preset sequence speed not controllable (issue #205), white-mode quirks on strips (issue #148).
  - src: https://aioafero.readthedocs.io/en/latest/ and https://github.com/jdeath/Hubspace-Homeassistant/issues/205
- [HIGH] **Hubspace app-defined groups, rooms, and scenes are NOT exposed: aioafero has no scene/group/room model or controller, and every write is a per-device REST PUT — so any 40-bulb zone change is 40 separate cloud calls, and the popcorn effect is structural, not a tuning problem.**
  - aioafero source tree and device.py contain no scene/group/room classes; commands go through send_service_request(device_id, states) -> PUT per metadevice. Issue #204 ('Rooms not importing', closed Dec 2025) confirms room import was attempted and doesn't work. HA's own scene engine also fires per-light service calls sequentially. Nothing in the ecosystem batches multiple devices into one API call; if the raw Afero API has a group-command endpoint, no community code uses it (worth checking in the API research track).
  - src: https://github.com/Expl0dingBanana/aioafero (src/aioafero/v1/models, controllers) and https://github.com/jdeath/Hubspace-Homeassistant/issues/204
- [HIGH] **aioafero hardcodes throughput ceilings that will strangle a 200-bulb scene apply: aiohttp TCP connector limited to 3 connections per host, MAX_RETRIES=3 with tiny linear backoff (0.25s*n) on 429/503/504, immediate hard-fail on 403, and per-device state-poll pausing after 3 consecutive 403s.**
  - From v1/__init__.py and v1_const.py: retried statuses are exactly 429/503/504 (ExceededMaximumRetries after 3), backoff 0.25/0.5/0.75s; 403 raises HTTPForbidden instantly; STATE_FETCH_FORBIDDEN_LIMIT=3 pauses per-device polls (added 9.0.1 Aug 9, 2026 — meaning real users hit repeated 403s on state GETs). With 3 parallel connections, 200 sequential-ish PUTs at ~150-300ms each ≈ 10-20s to issue a full-canopy scene — far outside the <2s spread target. A custom bridge must raise the connector limit and empirically find the 429 onset; the 429-retry code proves Afero does send 429s.
  - src: https://raw.githubusercontent.com/Expl0dingBanana/aioafero/main/src/aioafero/v1/__init__.py and https://raw.githubusercontent.com/Expl0dingBanana/aioafero/main/CHANGELOG.rst
- [HIGH] **Official troubleshooting docs confirm a per-ACCOUNT rate-limit quota shared by all clients: 'concurrent clients (phone app, Home Assistant, scripts) compete for the same quota' — which validates Home Depot's separate-account-per-vignette advice and suggests splitting the 200-bulb canopy across accounts multiplies write budget.**
  - aioafero troubleshooting guide attributes 429s and stale/slow data to multiple clients on one account and prescribes longer polling_interval or fewer simultaneous integrations. No numeric req/min limit is published anywhere in the ecosystem. Multi-account is natively supported in the HA integration: config entries are keyed unique_id=username.lower() with no single_instance restriction, so 5+ accounts run side-by-side; whether Afero also throttles per source IP (all kiosk traffic NATed) is unknown and must be bench-tested.
  - src: https://aioafero.readthedocs.io/en/latest/ (troubleshooting) and https://raw.githubusercontent.com/jdeath/Hubspace-Homeassistant/main/custom_components/hubspace/config_flow.py
- [HIGH] **Polling architecture and defaults: current v8.3.0 uses Conclave push by default with REST true-up polling at 900s (15 min) for new installs; pre-8.3 default was 30s account polling; HA options floor polling at 2s ('polling_too_short' error); aioafero library defaults are 30s state / 3600s discovery / 21600s firmware-version polls.**
  - Poll cost scales linearly with device count: state fetches are per-device GETs to /v1/accounts/{acct}/metadevices/{id}/state gathered through the 3-connection cap. Real-world cost datapoint: 14 lights polled at 5s consumed ~1.5 GB/day (issue #216, Dec 30 2025), ~6KB per device state response; 200 bulbs at 5s would be ~50 req/s attempted and tens of GB/day — do not plan tight polling; use Conclave for state and poll rarely. Emkraan's rival integration uses 30s delta polls floored at 2s 'because Afero rate-limits aggressively'; matterbridge-hubspace uses 30s (min 5s).
  - src: https://github.com/jdeath/Hubspace-Homeassistant/issues/216 and https://raw.githubusercontent.com/jdeath/Hubspace-Homeassistant/main/custom_components/hubspace/const.py
- [HIGH] **Conclave — Afero's push channel — was reverse-engineered and shipped opt-in in aioafero 9.3.0 / enabled-by-default in HA 8.3.0 on Sep 15, 2026: TLS socket to conclave-stream1.afero.net:443, newline-delimited JSON with zlib compression, ~60s server heartbeats, subscribe-ONLY (all writes remain REST).**
  - Access requires a short-lived token from POST /v1/accounts/{accountId}/conclaveAccess (distinct from the OAuth bearer), login must complete <60s, stall detection after ~2 missed heartbeats (~120s), auto-reconnect with exponential backoff, pushes attr_change/status_change plus device add/remove envelopes into the same cache REST fills. For the kiosk this is the state-verification rail (detect wrong/missed bulbs in near real time without poll storms) — but it is 4 days old at research time (protocol 'conclave 2.7.3' per issue #228), so an 8h soak must validate its stability before relying on it for show ops.
  - src: https://raw.githubusercontent.com/Expl0dingBanana/aioafero/main/docs/user/conclave.rst and https://github.com/jdeath/Hubspace-Homeassistant/issues/228
- [HIGH] **Auth is Keycloak OAuth at accounts.hubspaceconnect.com (realm 'thd', client_id 'hubspace_android', redirect hubspace-app://loginredirect) with very short-lived access tokens (~118s per Emkraan; changelog: expires_in minus 2s buffer); since aioafero 9.0.0/HA v8.0.0 (Aug 8-9, 2026) passwords are no longer stored — sessions live on the refresh token, with OTP/MFA supported at login.**
  - Breaking change caused a login-regression cluster (issue #256 Aug 18, 2026). The ~2-minute access-token life means any bridge must refresh constantly and proactively; Emkraan patches upstream aioafero with a 20s TOKEN_REFRESH_MARGIN because refresh-token failures caused infinite retry loops with no fallback to full login. For a 5-day retail activation: persist refresh tokens per account, implement full re-login fallback, and rehearse token revocation/password-change scenarios.
  - src: https://github.com/Emkraan/homeassistant-hubspace (README + custom_components/hubspace/aioafero/NOTICE.md) and https://raw.githubusercontent.com/Expl0dingBanana/aioafero/main/CHANGELOG.rst
- [MEDIUM] **Scale evidence: the largest publicly documented deployment is 143 devices, and it suffered intermittent HA bootstrap failures ('Bootstrap stage 2 timeout' inside aioafero wait_for_first_poll, Jan 2026) that were never root-caused — nobody in the community visibly runs ~200 Hubspace devices on one account, so the canopy operates beyond all documented field experience.**
  - Issue #222 (143 devices, HA 2026.1.2) resolved only empirically after upgrading to HA 2026.2.2; forum deployments are mostly 1-7 devices (fans, a dimmer, a dehumidifier); Hubitat port tester ran 7 fans. Historical latency complaint: 120s state-read delays with the 2023-era integration (issue #34, obsolete architecture). Positive datapoint: a single Home Depot dimmer ran a year with zero attention (HA forum, Mar 2026). The 200-bulb single-account configuration is unprecedented and must be treated as original research at the Sep 23 bench gate.
  - src: https://github.com/jdeath/Hubspace-Homeassistant/issues/222 and https://community.home-assistant.io/t/hubspace-formal-integration-through-ha/702572
- [HIGH] **Cloud reliability incidents are documented but short: a ~43-minute window of HTTP 500 Internal Server Error + connection timeouts on api2.afero.net per-device state endpoints on Jul 27, 2026 (issue #240); upstream aioafero did NOT retry 500/502 or connection errors (only 429/503/504) until Emkraan patched it — a stock bridge freezes on stale data during such windows.**
  - Emkraan's NOTICE.md also documents that aioafero's ~30s state-poll loop swallowed exceptions without emitting DISCONNECTED events, 'leaving devices frozen on stale data indefinitely' — directly relevant to the kiosk's <60s recovery target: the bridge must add its own disconnect detection and 500/502/timeout retry. Platform-churn warning: the Myko brand (also Afero-based) was force-migrated to Tuya-based Myko+ in Jan 2026, instantly breaking all community integration access for those users (issue #223) — precedent that Afero-platform access can vanish with a vendor decision; maintainer Expl0dingBanana said (Oct 2025) Afero never responded to requests for sanctioned local control.
  - src: https://github.com/jdeath/Hubspace-Homeassistant/issues/240 and https://github.com/jdeath/Hubspace-Homeassistant/issues/223
- [HIGH] **No transition/fade support exists anywhere in the stack — the light controller docs document no fade or transition-time parameter — so canopy 'mood' scenes must be designed as hard cuts, slow cloud-stepped drifts (API-call-expensive and rate-limit-risky), or offloaded to on-bulb 'sequence' preset effects which run autonomously after one command per bulb.**
  - color-mode 'sequence' triggers built-in animated presets on compatible bulbs/strips (speed not adjustable via API per issue #205). Exploiting on-device effects converts a continuous animation from ~N calls/sec forever into N one-shot calls per scene change — likely the only cloud-path way to get living, breathing canopy motion within quota; bench must confirm which A19 SKU presets exist and how they look.
  - src: https://raw.githubusercontent.com/Expl0dingBanana/aioafero/main/docs/user/controllers/lights.rst
- [HIGH] **Ecosystem map beyond jdeath: Emkraan/homeassistant-hubspace (created Jul 27, 2026, pushed Sep 19, 2026, 0 stars) is a from-scratch rival focused on exactly this project's failure modes (per-device availability, self-healing, stale-data tolerance, proactive token refresh) with a patched vendored aioafero; matterbridge-hubspace bridges to Matter (30s/min 5s polls); homebridge-hubspace and a Hubitat port exist; hubspace-ng is dead (last push Mar 2, 2024, v0.0.4); no real Node-RED node or MQTT bridge exists.**
  - Emkraan's patch list is effectively a free failure-mode catalog for the kiosk bridge team (token deadlock, 500/502/conn-error retry gaps, silent stale-poll loop) but the project has zero community validation — mine its diffs, don't adopt it blind. matterbridge-hubspace (Apache-2.0, Node 20.19+, 130 commits, 0 stars) offers a second protocol path (Matter) still backed by the same cloud. For the bespoke replacement-app pitch: the entire community stack is unofficial, ToS-gray, reverse-engineered, and Afero has ignored cooperation requests — a client-facing product on this API carries platform-shutoff risk with Myko as precedent.
  - src: https://github.com/Emkraan/homeassistant-hubspace and https://github.com/kirchmeyer/matterbridge-hubspace and https://github.com/shawngmc/hubspace-ng

## Bench tests
- Rate-limit discovery (the one number nobody publishes): on one dedicated account, ramp sustained per-device state PUTs to api2.afero.net (1, 2, 5, 10, 20 req/s) from one IP and log time-to-first-429/403/503 and recovery time; repeat with 5 accounts through the same NAT to prove quota is per-account (not per-IP) before committing to the 5-zone account split.
- Full-canopy scene apply: with aioafero patched to connector limits of 3 (stock), 10, 25, and 50, command 40 then 200 bulbs simultaneously; measure command-issue duration, first-to-last visible bulb spread (video at 60fps), wrong/missed bulb count over 100 scene changes, and 429 onset — this directly validates or kills the <2s spread / zero-miss acceptance targets.
- Conclave soak: run aioafero 9.3.0 with enable_conclave=True for 8+ hours against ~200 devices; log CONCLAVE_* lifecycle events, heartbeat gaps, reconnect frequency, and push latency (wall-clock from bulb change to attr_change event); verify no silent zombie sessions (feature is days old — assume nothing).
- Token endurance: verify refresh-token-only auth (aioafero 9.x flow, ~118s access tokens) survives 8h continuous operation and a 15-min WAN cut; measure time from internet restoration to first successful command (target <60s) and confirm full re-login fallback works when the refresh token is invalidated (password change at Home Depot account level).
- On-bulb 'sequence' effects on the actual EcoSmart A19 SKU: enumerate available preset effects via metadevice functions, trigger color-mode=sequence on 40 bulbs with one PUT each, and evaluate whether autonomous on-bulb animation gives acceptable 'living canopy' motion without continuous cloud writes (also test the documented limitation that sequence speed is not API-controllable).
- State-fetch load test: measure per-device GET /metadevices/{id}/state response size and latency for the A19 bulbs at 200-device scale, then verify 900s REST true-up + Conclave keeps kiosk state accurate enough to detect a manually power-cycled bulb within one scene cycle (mirrors the 400-on-split-devices regression fixed Sep 13, 2026 in PR #262).

## Open questions
- What is the actual numeric per-account rate limit (requests/min) and does Afero also throttle per source IP or per OAuth client_id? No community source publishes it; only the retry code (429/503/504) and 'clients compete for the same quota' guidance prove limits exist.
- Does the raw Afero API expose Hubspace app groups/scenes as commandable metadevices (one call -> many bulbs)? aioafero ignores rooms/groups entirely and the HA rooms import is broken, but the app itself creates groups — if a group-state PUT exists it changes the whole canopy architecture (question for the cloud-API research track / mitmproxy of the official app).
- Is Conclave (4 days old in aioafero) stable over multi-day sessions and does Afero rate-limit or expire conclaveAccess tokens under 5 concurrent accounts? Also: can Conclave carry commands in the official app's usage even though the community client is subscribe-only?
- Why did 143 devices intermittently blow HA's bootstrap ('stage 2 timeout') and does aioafero 9.3.0's Conclave-first architecture fix first-poll time at 200 devices, or does wait_for_first_poll still gate startup on ~200 sequential state GETs through 3 connections?
- Does any Hubspace A19 firmware quirk (per-bulb command debouncing, Wi-Fi power save latency) add variance beyond cloud latency — i.e., even with unlimited API budget, what is the floor for first-to-last spread across 200 bulbs on one 2.4GHz network?
- Platform risk for the bespoke app pitch: Myko's forced Jan 2026 migration off Afero broke all community access overnight, and Afero ignored the maintainer's partnership attempts (Oct 2025) — what contractual assurance can Home Depot/Hearst obtain from Hubspace before pitching a client-facing product on this reverse-engineered API?
