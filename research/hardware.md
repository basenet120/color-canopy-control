# hardware

**HEADLINE:** Every relevant Hubspace device is Leedarson-built ESP32 (FCC-confirmed ESP32-U4WD in the current A19 RGB bulb) speaking an Afero cloud data model that exposes RGB+CCT+named effects and a power-restore setting but NO per-command fade/transition — and the ESP32s ship with download mode eFuse-disabled, so custom firmware on stock bulbs is effectively impossible; plan fades in the bridge or via built-in autonomous effects.

- [HIGH] **The 12A19060WRGBWH1 bulb's FCC ID is 2AB2Q-12A800STQT and the FCC filing explicitly names the SoC: Espressif ESP32-U4WD, with 'other functions disabled via software'; grant date Nov 18, 2022; Wi-Fi 802.11b/g/n HT20/HT40 2412-2462 MHz at 0.074W conducted, BLE 1M 2402-2480 MHz at 0.007W.**
  - This is the definitive chip ID for the exact hero-piece bulb: an ESP32 (Xtensa LX6, embedded flash U4-series) running Afero firmware, not Realtek/Beken and not a discrete Afero radio module. Grantee 2AB2Q is LEEDARSON LIGHTING CO., LTD; the manual lists Leedarson America Inc., 300 Technology Court SE Suite 100, Smyrna GA 30082 as FCC responsible party. EcoSmart/Hubspace bulbs are Leedarson ODM products.
  - src: https://electric.garden/leedarson-lighting-2ab2q/led-lamp-12a800stqt
- [HIGH] **Leedarson's universal Hubspace Wi-Fi modules are ESP32-based across generations: LA02301 (FCC 2AB2Q-LA02301, grant 2020) is an 'ESP32-U4WDH SiP with embedded 4MB flash' per its own FCC user manual, and the newer LA02305 (grant 2023, updated through Jan 2026) is again ESP32-U4WDH, Xtensa LX6 up to 160 MHz, Wi-Fi b/g/n to +19 dBm and BLE +8 dBm; an LA02306 module was granted Sep 12, 2025 (chip not yet public).**
  - So 2020-2026 Hubspace lighting/plug/switch hardware is consistently single-family: ESP32 classic with 4MB in-package flash. There is no Beken/Realtek anywhere in the lineup, which rules out OpenBeken/LibreTiny/tuya-cloudcutter-style approaches entirely.
  - src: https://fccid.io/2AB2Q-LA02301 and https://electric.garden/leedarson-lighting-2ab2q/wireless-module-la02305
- [MEDIUM] **Custom firmware on stock Hubspace devices is effectively blocked: community flashing attempts found the ESP32 bootloader's Download Mode disabled (eFuse-burned), so GPIO0-grounding serial flashing fails; the only proven path is physically replacing the module (documented M5Stack Stamp transplant with LED channels rewired to GPIO25/26/18/19/22).**
  - The Home Assistant thread covers Hubspace-family devices (Defiant HPPA11CWB plug, Commercial Electric recessed kit with Leedarson module LA02301, HPDA311CWB dimmer). A 'Factory' pin enables a 460800-baud serial protocol that remains unreversed. Assume Secure Boot + flash encryption eFuses; treat bulbs (potted, soldered leads, inaccessible serial pads per the EcoSmart disassembly thread) as non-flashable for this project's timeline.
  - src: https://community.home-assistant.io/t/help-trying-to-flash-esp32-in-home-depot-bulb/326294 and https://community.home-assistant.io/t/ecosmart-hubspace-1006-931-917-disassembly-photos/527104
- [HIGH] **The Afero cloud data model for these bulbs exposes: color-rgb as raw RGB bytes {r,g,b} 0-255 (not hue/sat), color-mode enum (white | color | sequence, plus night-light on some fixtures), numeric color-temperature (A21: 2200-6500K in 100K steps; some fixtures instead expose a discrete named-K list), brightness 1-100%, and named color-sequence effects — and there is NO transition/fade-time parameter anywhere in the light PUT model.**
  - Verified by reading the full aioafero light controller source (set_state signature: on, temperature, brightness, color_mode, color, effect, force_white_mode, numbers, channel — no duration/transition) and the real A21 device dump (tests/v1/data/light-a21-raw.json). Any cross-fade for the Color Canopy must be synthesized by the kiosk bridge as stepped brightness/color writes through the cloud, or delegated to the bulbs' built-in autonomous effects.

- [HIGH] **Built-in autonomous effects on the A21/A19 family: preset instance = flash, fade-3, fade-7, jump-3, jump-7, custom; custom instance = sleep, july-4th, clarity, focus, wake-up, getting-ready, rainbow, chill, dinner-party, moonlight, valentines-day, christmas, nightlight; plus a speed control (functionClass 'speed'/'color-sequence') ranging -10..+10 step 1.**

## Bench tests
- Fade smoothing characterization: command an abrupt color change (e.g., red->blue) and brightness change (100->10%) on one 12A19060WRGBWH1 and film at 240fps; measure whether firmware applies internal ramping (ms of smoothing) or hard-cuts — the API has no transition parameter, so perceived scene-change quality depends entirely on this.
- restore-values semantics: for each of restored / not-restored / partial-restore, set a saturated color scene, kill mains power 10s, restore, and record exact power-on state (on/off, color, brightness) and time-to-light; confirms canopy behavior after a breaker trip mid-show and whether bulbs storm the Wi-Fi/cloud on reconnect.
- Zone fan-out latency (the go/no-go metric): from the Python bridge via aioafero, PUT a full scene to 40 bulbs on one account/AP; measure Apply->first bulb visibly changing, first-to-last spread, and p95 over 100 scene changes; repeat with all 5 zones (200 bulbs, 5 accounts) firing within 1s of each other to detect cloud rate limiting (watch for HTTP 429/403 from api2.afero.net).
- Built-in effect evaluation: run fade-3, fade-7, jump-3, jump-7 and the 13 custom presets (rainbow, christmas, etc.) at speed -10, 0, +10 on a 3x3 bulb grid; assess visual sync drift between adjacent bulbs over 10 minutes (effects free-run per-bulb; if drift is objectionable, canopy 'motion' scenes must be bridge-driven).
- Provisioning throughput: time QR-scan onboarding of 10 bulbs to one account (target data: min/bulb), then scan 2 of them from a second account to verify ownership transfer behavior and any de-provisioning lag; extrapolate the 200-bulb install window for Oct 20-23.
- Wi-Fi association scaling: join 40 bulbs to a single 2.4GHz AP (HT20, WPA2), confirm all hold association for 8h idle + hourly scene changes with zero drops (bulb wifi-rssi and wifi-steady-state polled via API as the log); repeat at 60 clients to find the practical per-AP ceiling before the 5-AP layout is finalized.
- Thermal soak in canopy fixture: mount 9 bulbs at final grid pitch in the actual socket/shroud hardware (manual forbids totally enclosed fixtures), run 8h at 100% white; log external bulb-neck temperature and check for thermal dimming/color shift or dropouts.
